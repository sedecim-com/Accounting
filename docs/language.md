## 0. The request, and the three layers it hides

The instruction is two sentences from the same day: *all code based on English and, from there, translated into different languages leaving Spanish first*, and its two refinements: ***everything at origin in English, and the whole user experience adjustable to another language, configuring Spanish first***, and then ***everything into English at origin. Everything***. "Everything at origin" reaches comments, commit messages, documentation, dated reports, migration names, persisted vocabulary and published contracts — without the list of exceptions the first version of this document had proposed —; "the whole user experience" reaches the CLI help, the manuals and the wiki. The only thing that cannot go to English at origin is what **is not origin**: rows already written in the database, and proper names. To honour it without breaking what already works, three layers that are mixed today must be separated, because **they do not change the same way**:

| Layer | What it is | Language | How it changes |
|---|---|---|---|
| **What the machine and the programmer read** | identifiers, file names, comments (new and existing), commit messages, catalog keys, error codes, canonical command names, new columns and values | **English**, and only English | renaming and translating, with a *codemod* and with the instruments updated in the same commit |
| **What the user reads** | CLI help and messages, API errors, report labels, panel questions and labels, `doctor` notices, agent answers, **and the documentation**: README, manuals, wiki and governing documents | **the user's**: Spanish first and by default, English second, others later | extracting the English source into a **typed** catalog and rendering in the resolved locale; documentation, with an **English source and a Spanish twin** per page |
| **What is persisted vocabulary or a published contract** | panel keys and values, account roles, `CHECK` lists, migration names, error codes, `x-*` keys and JSON row keys, CLI flag values | **English** in the source; what is already stored gets **migrated** | renaming the source **and** migrating the data under RLS, with an alias window and a contract version bump (§3.9) |
| **What is not origin** | rows already written (posted entries, `audit_log`, text written by the model or by a human), artifacts already signed or hashed, and proper names and official acronyms (SAT, CFDI, RFC, IMSS, UMA, DIOT, REP, IRS, W-2) | whatever it has | untouched: rows are history and proper names are not translated |

Confusing the layers is the mistake this document exists to prevent: renaming a persisted value is a **data migration** under RLS with an alias window, not a `sed`; renaming an error code or a JSON row key is a **contract version bump**, not a rename; and "putting the help in Spanish" without deciding what `ux:status` measures against turns red a ratchet that today guards exactly the opposite.

## 2. The rules

1. **The machine layer is English, and what is new is born English from day one.** Identifiers, file names, comments — new ones, and existing ones by tranche (I20) —, **commit messages**, catalog keys, error codes, columns, values, **migration, script and `npm run` names**: in English. A lint makes it fail in CI for what is new; what exists enters a **per-file** baseline that only shrinks. This inverts `CONTRIBUTING.md:158` and `README.md:345`, which are rewritten in the same PR that installs the rule. **The artifacts of this plan obey the rule from their name**: `scripts/language/`, `docs/language-baseline.json`, `house/english-identifiers`, `npm run language:status`, `src/i18n/`, and this very document (`docs/language.md`, with its twin `language.es.md`).
2. **Every string a user reads has a key and an English source, and the Spanish catalog is complete before the key is used.** The catalog is **typed**: `es.ts` is declared as `Record<keyof typeof EN, string>`, so a key without a translation is a `tsc` error, not a warning; a sync test guards what the type cannot see (parameters, empties, wrong language, orphans).
3. **What is persisted is persisted as key and parameters, and rendered on read.** Entry descriptions, audit reasons, period names, payroll calculation notes: the row stores `key` + `params` **and** the English prose in the column it always had; the output renders the key in the resolved locale. History is not backfilled and is shown as it is.
4. **Persisted vocabulary and published contracts also go to English, and are renamed with a net.** Panel keys and values (53 + 93), the 36 account roles, 43 `CHECK` values, the 11 `as const`, 24 error codes, 10 `x-*` keys and 1,391 JSON row keys, 35 migration titles, 4 tables and 117 columns, CLI flag values, the *golden* keys. First they are **registered** with an English gloss (I4: the registry is the `old → new` map and the net for the criteria), and then renamed by class with a **data migration under RLS**, an alias window in readers and gates, and a version bump where there is a contract (§3.9). New ones are born English from I3. **Proper names are not vocabulary**: SAT, CFDI, RFC, IMSS, UMA, DIOT, REP, PPD, PUE, INPC, CLABE stay, as IRS or W-2 stay in Spanish.
5. **Language, format and jurisdiction are three things.** The **language** follows the user (`--locale` > `MNEMOSINE_LOCALE` > config > tenant preference > `es-MX`, the order §3.4 details; in REST, `Accept-Language`). The **format** — numbers, dates, currency — follows the jurisdiction and the entity's currency, never the language, and only in the `table` branch. **Artifacts for third parties** follow the authority: the SAT's XML in Spanish, the IRS forms in English, even if the user reads the other.
6. **The instruments measure the source, not the render.** `ux:status`, `generate-cli-reference.ts`, the bilingual matrix and the criteria keep seeing the canonical English (they run with `--locale en-US` pinned, as they already pin the width); the catalog applies at render time. Help is translated **by key**, never using the English prose as a lookup key.
7. **Identity before prose.** Nothing identified today by a Spanish text — floor statements, criteria looked up by statement, baselines by `detail` — is translated before it has an `id`.
8. **Documentation is user experience, all of it — and the obligation enters with I21 and I26, not before.** The README, the manuals, the wiki, the governing documents **and the dated reports** will have an **English source and a complete Spanish twin** before being published (§3.8), and a change in the source and its translation will travel in the same PR. Until I2 measures it and I21 and I26 deliver it, **every page published without a twin enters the `language:status` baseline, which only shrinks** (§3.2): there is no obligation this document claims fulfilled before the instrument exists. What does comply from today is what this plan publishes as its own: this document (`language.md` + `language.es.md`) and its wiki page (`Code-language.md` + `Code-language.es.md`), both with `source_sha`. The 23 reports under `docs/investigacion/2026-09-06-idioma/` that this same PR publishes are the **first entry of that baseline** (`find docs/investigacion/2026-09-06-idioma -name '*.md' | wc -l` → 23) and I26 carries them. This was the owner's decision on 2026-09-06 (§6), in three ever-wider steps: "all the code", "everything at origin", "everything. Everything".

## 3. The machinery

### 3.1 One population, one lexicon

Lint and meter count **the same thing with the same walker**: identifiers in declaration position (variables, functions, classes, types, enums and members, parameters, properties, destructuring), tokenized by *camel/Pascal/SCREAMING*, flagged if a token is in the list of Spanish roots (`scripts/language/lexicon.ts`: ~1,128 roots from the inventory, 213 neutrals — SAT/IMSS acronyms, brands, identical words —, and a list of **domain terms** that starts empty and only grows with a reason per entry) and none neutralizes it. Written exemptions: ≤ 2 letters and `snake_case` only in interface members (the style of what is persisted). The lexicon has its spec: 0 false positives over the nine English folders and ≥ 98 % accuracy over the 200 sampled declarations.

### 3.2 The meter: `npm run language:status`

Like `catalogo:estado` and `ux:status`: it walks the tree, writes its block between markers in this document, `--check` in CI (next to `ux-status`, `ci.yml:176`), `--apretar` only lowers, `--sembrar` **refuses on a dirty tree**. The lanes, each with its published command:

### 3.3 The lint: `house/english-identifiers`

An own ESLint rule, **inline** in `eslint.config.mjs` (no package), at **error** level over `src/`, `tests/` and `scripts/`, with a **per-file** baseline in `docs/language-baseline.json` (`{path: flagged}`; no entry = 0) that can only be lowered; the rule fails if a file exceeds its baseline, and a test fails if an entry exceeds what is measured or names a nonexistent file. False positives: `// language-allow: <reason>`, counted by the meter. `--max-warnings` is not used: that global cap already states three different figures in three files.

### 3.4 The typed catalog, the resolver and the formatter

- **`src/i18n/en.ts`** is the source (`as const`); **`src/i18n/es.ts`** is declared `Record<keyof typeof EN, string>`; `t(key, params)` with own plural and select over `Intl.PluralRules` (Node ≥ 20 guarantees it): **zero dependencies**, keys that `tsc`, `codigoDe` and the meter see. The sync test covers what the type cannot: equal parameters between languages, empty strings, wrong language, orphan keys, and that `LANGUAGES[0] === 'es'`. A `__TRANSLATE__` marker in `en.ts` is rejected. **For now there are two languages**, `es-MX` and `en-US` (owner's decision, 2026-09-07); the mechanism does not know how many there are, and a third one will be one more file and one line in the sync, not a tranche.
- **`src/i18n/locale.ts`**: `resolveLocale()` synchronous and without a database: `--locale` (global flag in `FLAG_DICTIONARY`, one meaning) > `MNEMOSINE_LOCALE` (with `MNEMOSINE_LANG` as a permanent alias) > `~/.mnemosine/config.json` > `./mnemosine.config.json` > `tenants.settings.locale` (JSONB that already exists, no migration) > `es-MX`. `es` is canonicalized to `es-MX` and `en` to `en-US`. In REST: `Accept-Language` > tenant > `es-MX`, and the response declares `Content-Language`. **One only** for the interface and the agent; `resolveLanguage` (`config.ts:1119`) starts reading it. `vitest.config.ts` pins `test.env.MNEMOSINE_LOCALE = 'en-US'` so that the 1,025 CLI assertions compare the source.
- **`src/i18n/format.ts`**: `formatMoney`, `formatDate`, `formatNumber` over `Intl` with the `formatLocale` derived from the jurisdiction and the entity's currency (`jurisdictionOf(entity)`), **only for `table` and prose**; `json`, `csv`, `ndjson` and `md` do not change (`presentation.spec.ts:10-14`). Currency with **ISO code** (`1,234.56 MXN`), ISO dates in tables. `formatMoneyMx` stops carrying the locale in its name, with a deprecated alias. CI pins `full-icu`, because with `small-icu` every locale silently falls back to `en-US` and today no test detects it.

### 3.5 CLI help, by key

Commander 15 offers `configureHelp`, `helpOption`, `helpCommand` and `configureOutput`. The description of each command is declared in English in the source and rendered by **key** (`help.<family>.<leaf>.description`), never by looking up the English prose as the key: editing a description cannot silently orphan a translation. Startup order rules: descriptions are set before `parseAsync` (`mnemosine.ts:818-826`), so the locale is resolved **before** registering the families, reading `--locale` by hand from `process.argv`. `CliError` gains `{key, params}` and `reportError` renders; the 305 service messages that today reach the user raw through `reportError` go through the same path once `AppError` gains `key` (I9).

### 3.6 What is persisted: key and parameters

A migration with **the number the directory says** (append-only; today 070 was already taken by another branch): `journal_entries.description_key` + `description_params JSONB`, likewise in `journal_entry_lines`; `audit_log.reason_key`; `ai_drafts.review_kind` (replaces the `LIKE 'auto-post by threshold%'`); `fiscal_periods.period_key` (`'2026-01'`) **keeping `period_name`** (it enters the view's `GROUP BY` and the `ILIKE` search) and deriving it. New writers write key + parameters **and** the English prose in the old column. **No backfill of history** (041, 033, NIF B-1: the trail is read as it was written). The **`Concepto` of Anexo 24 is rendered in Spanish, always**, from the key; artifacts already stored with their hash do not change and the commit says so.

### 3.7 The renames, by subsystem and with a *codemod*

`scripts/language/rename.ts` (over `ts-morph`: `SourceFile.move()` rewrites every import of `src`, `tests` and `scripts` in one call) plus `verify-rename.ts` (`git grep` of the old name → 0, excluding migrations, audits, HISTORY and the archive). **In the same commit** it updates what `tsc` does not see: the regexes, paths and mutant anchors of `criterios.ts`, the **four** threshold tables, the 81 `vi.mock` by string and the 43 literal paths in `tests/`, the `typeof import()` of `conducta.ts`, `ci.yml` (:153-176, :225, :304, :312, :423), `CODEOWNERS` (7 paths without a gate), `package.json`, the regenerated catalog block (616 citations) and the paths cited in `docs/`. A rename PR **touches no string literal**. The manifest is resealed only when the sealed file's `diff` is import specifiers, with a mandatory `--why`; in any other case the manual is reread (`corpus-manifiesto.ts:171`). The net: `npm run typecheck:tests`, the four `--check`, `plan:status --piso --exigir`, `npm run mutantes` 120/120, in a clean worktree. The real rehearsal is a module with 0 criteria, 0 threshold and 0 manifest (`sat/diot/hechos.ts → facts.ts`).

The order comes from the measured coupling, from the outside in: the 17 leaves without coupling → `scripts/` with `npm` aliases for one version (D8) → the internal API that crosses folders, by origin and from least to most consumption → SAT, DIOT, Anexo 24 and MX payroll (touching no literal: hashed artifacts do not change) → `tests/` → the **sealed engine** (`criterio-cierre.ts` with its four threshold tables moved at once; `posting.ts`, `period-close.ts`, `ledger-checks.ts`, `report-service.ts`, `iva-cash-basis.ts`, `ar-ap-posting.ts`, with seven sealed sources reread) → `src/plan` and the instrument's helpers, last of all.

### 3.9 Persisted vocabulary and published contracts: renaming with a net

Four classes, four different nets, and the I4 registry as the map of all of them:

- **Persisted values** (panel, `account_roles.role`, `CHECK`, `as const`, `credit_notes.type`, `reconciling_items.tipo`…): one tranche per class. A data migration with the `SET LOCAL row_security = on` loop of `docs/migraciones.md` that rewrites the rows (in the panel, the **three** columns: `key`, `options`, `resolved_value`/`default_value`); the readers accept the old and the new value for **one version** (`avisarValorDesconocido` stops being the destination); the `CHECK` admits both during the window and is tightened when it closes; the CLI gates that expose the value (`--type cheque-en-circulacion`, `bank-command.ts:1775`) follow the catalog's R9 deprecation protocol; the criteria that anchor literals (`criterios.ts:1436, 1615-1721, 2162, 3438`) and the 247–511 test assertions are rewritten in the same PR. The meter counts "Spanish persisted values" per class and only lowers.
- **Published contracts** (24 error codes, 10 `x-*` keys, 11 response keys, 1,391 interface members that are `--json`/REST/GraphQL row keys, `SCHEMA_VERSION` in `output.ts:34`): **`SCHEMA_VERSION 2`** and `docs/openapi.json` regenerated; the envelope emits the new `code` and `details.legacy_code` for one version; the CLI accepts `--schema-version 1` during the same window; the command catalog and the three wiki pages that cite codes are updated. It is the tranche that **breaks clients** if done without a window, which is why the window is part of the criterion.
- **Migration names** (35 Spanish titles; the number does not change and the 4 duplicates are not renumbered): the migrator registers by file name (`migrate.ts:66-68`), so renaming without more would re-run them. `migrate.ts` gains a `LEGACY_FILENAMES: Record<new, old>` map that treats an applied old name as the new one, and an idempotent write that updates `public.migrations.filename` on the first run; an integration test brings up a database with the old names and verifies that no migration repeats. The 17 criteria and the 84 citations in `docs/` that name migrations are rewritten with the map.
- **Schema objects** (4 tables, 117 columns — including the 77 that mirror a SAT/IMSS/DIOT attribute, which carry the original attribute name in `COMMENT ON COLUMN` —, 6 functions, 59 constraints/indexes/triggers): a `RENAME` migration without data; RLS is rediscovered by `tenant_id` (`rls-policies.sql:23-33`) and reapplied after every migration; `tests/integration/schema-contract.int.spec.ts` and `enum-contract.int.spec.ts` flag whatever lags behind; materialized views are recreated.

## 4. What does not change

- The seven invariants of [`AGENTS.md`](../AGENTS.md). A text catalog is not a door to the ledger.
- The **canonical command names** are English; the Spanish aliases are user experience (the translation layer of the verbs) and are kept as aliases.
- **Rows already written**: posted entries (041), `audit_log` (033), signed or hashed artifacts, and the text the model or a human wrote in the session (`ai_questions`, memory, skill drafts). They are history, not origin.
- **Proper names and official acronyms** (SAT, CFDI, RFC, IMSS, INFONAVIT, UMA, DIOT, REP, PPD, PUE, INPC, CLABE, SPEI): they are not vocabulary and are not translated.
- Migration numbers and the four duplicates (`docs/migraciones.md`): the title is renamed, never the number.

## 6. What the owner decides

The owner decided D1, D2, D5, D6, D7, D8 and D9 on 2026-09-06 with three sentences — "all the code", "everything at origin", "everything. Everything" — and D12 on 2026-09-07 ("only two languages for now"): here they stand as decisions, not as proposed defaults. Only D3 (the lint's scope from day one) remains open, and it blocks nothing.

- **D1 · Existing comments, documentation and commits — decided 2026-09-06: yes, everything at origin in English.** Existing comments are translated by tranche with a ratchet (I20); documentation moves to an English source with a complete Spanish twin (I21); commits in English from I22; dated reports too, in I26 (rule 8).
- **D2 · Domain terms — decided: everything is translated.** `poliza` → `journalEntry`, `balanza` → `trialBalance`, `nomina` → `payroll`, `agrupador` → `groupingCode`, `folio` → `folio` (it is an English word). Proper names and official acronyms (SAT, CFDI, RFC, IMSS, UMA, DIOT, REP, PPD/PUE, INPC, CLABE) are not vocabulary: they stay. The lexicon's domain-term list starts empty and only admits proper names.
- **D3 · Lint scope from day one**: `src/` + `tests/` + `scripts/` (**default**) or only `src/`.
- **D4 · J0.1 — settled 2026-09-07: renamed before merging**, on its own branch (PR #140), at the reviewer's request; the default held.
- **D5 · Published contracts — decided: to English**, with `SCHEMA_VERSION 2`, `details.legacy_code` and a one-version window (I24). It is the tranche that breaks clients if done without a window.
- **D6 · `tests/` and the instrument — decided: they are in**, names, helpers and the 4,831 `describe/it` titles (I19).
- **D7 · Migrations — decided: to English, the new ones and the 35 existing ones** (title, never the number), with `LEGACY_FILENAMES` in the migrator (I25).
- **D8 · `npm run` names — decided: to English**; the Spanish aliases last one version and `CLAUDE.md`, `AGENTS.md` and the 91 mentions are rewritten in the same PR (I13).
- **D9 · Is the CLI help translated? — decided 2026-09-06: yes, the whole user experience.** It inverts `bilingual-matrix.spec.ts:310-323`, `ux-status.ts:314`, `src/cli/README.md:396` and R8; the instruments measure the English source (rule 6).
- **D10 · A single locale setting** for the interface and the agent (**default**) or `agent_locale` as an override; `MNEMOSINE_LANG` as a permanent alias.
- **D11 · Presentation**: ISO currency code and ISO dates in tables (**default**) or symbol and locale.
- **D12 · Third language — decided 2026-09-07: only two languages for now**, `es-MX` and `en-US`. No `pt-BR` test; the mechanism stays ready for a third one without its own tranche.
- **D13 · Time zone per entity**: the two clocks of "today" (`CURRENT_DATE` vs `getMonth()`) and the container without `TZ` are real, but they belong to the J series (J0.6), not to this one.
